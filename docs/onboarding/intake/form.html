PCC Device Intake

One question per field. Fields marked "never defaulted" or "sensitive" are never guessed or filled in for you — an empty answer blocks the step that needs it. Fields marked "self-declared" record only what you attest, never a researched or inferred value. An evidence badge marked "stub" proves nothing yet: the vocabulary defines it, but no verifier is live for it today.

Identity

operator.displayName
What name should buyers and the network see for you or your shop?
This is the name that appears on every listing and job you accept.
class C
required for: register
operator.contactEmail
What email should we use for job notifications and key provisioning?
We need a channel to reach you about jobs, approvals, and account security.
class C
required for: register
operator.authority
Do you have the authority to offer this machine's time on PCC?
Only someone authorized to commit the machine's time may register it — this is never assumed.
class C never defaulted
required for: register

Device

device.description
In your own words, what is this device and what should buyers expect to get from it?
This seeds device identification and the search for a matching capability contract.
class C
required for: identify
device.vendor
Confirm the device's manufacturer/vendor.
The vendor name drives the adapter config and which kits can match this device.
class A
required for: register-device
device.model
Confirm the device's exact model.
The exact model is how we find the right manual, safety limits, and remote-control protocol.
class A
required for: register-device
device.serialNumber
What is the device's serial number (from its label)?
The serial number ties this specific unit to its device record.
class C
required for: register-device
device.firmware
Confirm the device's firmware version.
Firmware version affects which commands and safety behaviors are available (N83 G8).
class A
required for: register-device
device.adapterType
Confirm the adapter type PCC should use to talk to this device.
This selects the real adapter that will run jobs — it is never "mock" for a live device.
class A
required for: register-device

Location

location.cityCountry
What city and country is this device located in?
Buyers need a coarse location to judge shipping time and jurisdiction.
class C
required for: publish
location.streetAddress
What is the device's street address? (Private — never shown publicly; used for logistics only.)
We need this for couriers and installers, but it is never published — public listings only ever show city and country.
class C sensitive: do not write it here
required for: optional

Network

network.reachability
Is this device on the same local network as the agent host, and does it have a static IP?
This decides whether we can reach it directly or need pcc-node as a relay.
class C
required for: register-device
network.outboundHttps
Can this device (or its host) make outbound HTTPS calls?
Outbound-only connectivity lets us use pcc-node without opening any inbound ports.
class C
required for: register-device
network.inboundBlocked
Is inbound access to this device blocked by a firewall or NAT?
This confirms whether pcc-node's outbound-only design is required.
class C
required for: register-device

Safety

safety.supervision
Will this device run attended, unattended, or remote-supervised?
Supervision level is never assumed — it directly bounds which jobs are safe to accept.
class C never defaulted
required for: accept-jobs
safety.estop
Is there a physical e-stop? What type, and who can reach it?
An e-stop's presence and reachability is safety-critical and is never defaulted.
class C never defaulted
required for: accept-jobs
safety.hazards
What hazards does this device present (chemical, laser, heat, mechanical, biological)?
Hazard classes shape the safety envelope — an empty answer blocks job acceptance rather than assuming "none".
class C never defaulted
required for: accept-jobs
safety.limits
Confirm the safety limits we found for this device (e.g. max temperature, max volume, allowed materials) — or tell us if any are wrong.
Safety limits come from the manual, but only a human confirmation makes them binding — never a guess.
class B never defaulted
required for: accept-jobs

consumables.items
What consumables does this device use (materials, tips, filters, etc.)?
This lets buyers and the scheduler know what's needed to run a job.
class C
required for: accept-jobs
consumables.restockedBy
Who restocks these consumables, and how often?
This sets expectations for availability and avoids mid-job surprises.
class C

class C

Calibration

calibration.lastDate
When did you last calibrate this device? (self-declared)
This is self-declared only — we never infer or default a calibration date.
class C self-declared evidence: decl.self_attested (live)
required for: tier1
calibration.procedureRef
Which calibration procedure did you follow? (self-declared)
Research can suggest a procedure, but only your confirmation makes it the record — self-declared only.
class B self-declared evidence: decl.self_attested (live)

Evidence

evidence.executorDeviceId
Which device id actually executes the job?
This is the raw fact the evidence plan is built from — independence is derived from it, never asked directly.
class C
required for: tier1
evidence.observerDeviceIds
Which device ids (if any) only observe the job, without executing it?
An observer that isn't also the executor is what makes an inspection independent — we derive that, we don't ask you to assert it.
class C
required for: tier1
evidence.executionMode
Is this run against the real device, or a mock/dry-run adapter?
A mock or dry-run answer caps the job's evidence at tier 0 — it can lower the tier, never raise it.
class A evidence: confirm.execution_mode (live)
required for: tier1
evidence.camera
Is there a camera? Does it see the work area, does it see the output, is it fixed or handheld, and which device id captures it?
The camera must be a separate device from the machine — this is what lets us capture believable photo evidence.
class C evidence: capture.photo_nonced (stub — stub = proves nothing yet)
required for: tier2
evidence.operatorPresence
Is an operator present always, sometimes, or never during a job?
Operator presence shapes what kind of evidence and approval is realistic to collect.
class C
required for: tier1
evidence.approver
Who is the person who will approve evidence for this device? (identity only — their signing key is registered separately later.)
We need to know who will attest to job quality before we register how they sign.
class C evidence: approval.expert (stub — stub = proves nothing yet)
required for: tier2
evidence.controllerRunLog
Can the controller export its own execution log per job? If so, via API or file?
A per-job exportable log is what lets us build a trustworthy machine execution record.
class C evidence: machine.execution_log (stub — stub = proves nothing yet)
required for: tier1
evidence.instrumentSignsOutput
Does the instrument cryptographically sign its own output?
A self-signing instrument raises the evidence ceiling — but only once its signing key is registered (companion primitive: receipt.kernel_signed).
class C evidence: ident.registered_key (stub — stub = proves nothing yet)
required for: tier1
evidence.referenceSample
Do you have a reference sample with a known expected result?
A known-good test pair is the strongest cheap proof that the capability actually works.
class C evidence: measure.io_test_pair (stub — stub = proves nothing yet)
required for: tier1
