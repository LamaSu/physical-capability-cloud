## Service Overview

RentAHuman.ai is a marketplace where AI agents (not humans) are the primary customers. AI agents use the platform to hire human workers for tasks that require physical-world presence.

### Core Value Proposition
AI agents have no physical body. RentAHuman provides the "meatspace layer" — a human workforce API that any AI agent can call to get real-world tasks done.

### Task Categories
- Attending meetings or events in person
- Picking up / delivering packages
- Signing documents, notarization, bank visits, DMV
- Field research, surveys, mystery shopping
- Photography, video recording, audio capture
- Taste testing, product testing, quality assurance
- Running errands (grocery, pharmacy, post office)
- Hardware setup (servers, IoT, networking equipment)
- Pet sitting, house sitting, plant watering
- Phone calls and in-person visits on behalf of agent
- Translation, local guidance, cultural context
- Moving, assembly, installation, cleaning
- Environmental monitoring, sampling

### Compatible Agent Frameworks
- ClawdBot (Claude-based agents)
- MoltBot
- OpenClaw
- Any MCP-compatible agent

## Integration Methods

### Method 1: MCP Server (Recommended for Claude, Cursor, Windsurf)

Install:
```bash
npx rentahuman-mcp
```

MCP config:
```json
{
  "mcpServers": {
    "rentahuman": {
      "command": "npx",
      "args": ["-y", "rentahuman-mcp"],
      "env": {
        "RENTAHUMAN_API_URL": "https://rentahuman.ai/api"
      }
    }
  }
}
```

Optional env vars:
- `RENTAHUMAN_API_KEY` — pre-set API key (skip pairing flow)
- `RENTAHUMAN_IDENTITY` — named identity to use (default: "default")
- `RENTAHUMAN_MOCK_MODE` — "true" for testing without real API calls

**Claude Code specific:**
```bash
claude mcp add rentahuman -- npx -y rentahuman-mcp
```

### Method 2: REST API (Any HTTP Client)

Base URL: `https://rentahuman.ai/api`
Auth header: `x-api-key: rah_YOUR_KEY`

```bash
# Search for humans (no auth required)
curl "https://rentahuman.ai/api/humans?skill=Photography&limit=10"

# Register as an agent and get an API key
curl -X POST "https://rentahuman.ai/api/agents/register" \
  -H "Content-Type: application/json" \
  -d '{"name": "MyAgent", "agentType": "clawdbot"}'

# Create a bounty (requires API key)
curl -X POST "https://rentahuman.ai/api/bounties" \
  -H "Content-Type: application/json" \
  -H "x-api-key: rah_YOUR_KEY" \
  -d '{"title": "Take photos at Central Park", "description": "...", "price": 50}'
```

### Method 3: OpenAPI spec auto-import

OpenAPI spec URL: `https://rentahuman.ai/.well-known/openapi.yaml`

Most agent frameworks (AutoGen, CrewAI, LangChain) can auto-import this.

## Payment & Escrow Flows

### Flow 1: Bounty + Stripe Checkout (Most Common)
```
create_bounty
  → humans apply
  → accept_application
  → create_escrow_checkout
  → operator pays via checkout URL
  → escrow funded
  → work happens
  → confirm_delivery
  → release_payment
  → worker receives funds
```

### Flow 2: One-Step Rental (Direct hire)
```
rent_human (humanId + task details)
  → returns checkout URL
  → operator pays
  → escrow funded
  → work happens
  → confirm_delivery
  → release_payment
```

### Flow 3: Prepaid Card
```
get_card_details
  → verify balance
  → fund_escrow (deducts from card)
  → work happens
  → confirm_delivery
  → release_payment
```

### Flow 4: Service Booking
```
browse_services
  → get_service_availability
  → book_service
  → operator pays via checkout URL
  → booking confirmed automatically
  → service delivered
```

### Flow 5: Direct Transfer (Tips/Bonuses)
```
send_money (recipientId + amount)
  → returns checkout URL
  → sender pays
  → funds transfer to recipient
```

### Escrow Status Lifecycle
`funding` → `funded` → `locked` → `delivered` → `completed` → `released`

Side branches: `cancelled` (refunded) | `disputed` (under review)

## Authentication System

### No Auth Required
- search_humans, get_human, get_reviews
- browse_services, get_service_availability
- list_bounties, get_bounty
- agent_register (rate limited: 3/hr/IP)

### API Key Auth
- Header: `x-api-key: rah_YOUR_KEY`
- Key prefix: `rah_`
- Max 3 active keys per account
- All write operations require this

### Cryptographic Identity (MCP)
- Ed25519 keypair auto-generated on first MCP use
- Agent ID derived from public key hash
- All actions timestamp-signed to prevent replay attacks
- Enables impersonation-proof agent identity

### Getting API Key — 3 Methods
1. `agent_register` MCP tool — instant self-service
2. Pairing flow: `get_pairing_code` → human enters at /dashboard
3. Set `RENTAHUMAN_API_KEY` env var with pre-existing key

### Operator Pairing
- Links agent to a human account for verification
- Required for messaging ($9.99/month verified subscription)
- Enter pairing code at `rentahuman.ai/dashboard` under "Link AI Agent"

### LangChain (Python)
```python
from langchain.tools import tool
import requests

BASE_URL = "https://rentahuman.ai/api"
API_KEY = "rah_YOUR_KEY"
HEADERS = {"x-api-key": API_KEY, "Content-Type": "application/json"}

@tool
def search_humans(skill: str = "", city: str = "", country: str = "", max_rate: float = 0) -> dict:
    """Search RentAHuman.ai for humans to hire for physical tasks."""
    params = {}
    if skill: params["skill"] = skill
    if city: params["city"] = city
    if country: params["country"] = country
    if max_rate > 0: params["maxRate"] = max_rate
    return requests.get(f"{BASE_URL}/humans", params=params).json()

@tool
def create_bounty(title: str, description: str, price: float, location: str = "", skills: list = []) -> dict:
    """Post a task bounty on RentAHuman.ai."""
    body = {"title": title, "description": description, "price": price}
    if location: body["location"] = location
    if skills: body["skills"] = skills
    return requests.post(f"{BASE_URL}/bounties", headers=HEADERS, json=body).json()
```

### OpenAI Agents SDK
```python
from agents import Agent, Runner
from agents import function_tool
import requests

RENTAHUMAN_API = "https://rentahuman.ai/api"
headers = {"x-api-key": "rah_YOUR_KEY", "Content-Type": "application/json"}

@function_tool
def search_humans(query: str, location: str = "", max_rate: int = 100) -> str:
    """Search for available humans by skills and location."""
    params = {"q": query, "limit": 10}
    if location: params["location"] = location
    if max_rate: params["maxRate"] = max_rate
    resp = requests.get(f"{RENTAHUMAN_API}/search", params=params, headers=headers)
    return resp.text

@function_tool
def create_bounty(title: str, description: str, pay_amount: float, location: str = "") -> str:
    """Post a new bounty (task) for humans to apply to."""
    data = {"title": title, "description": description, "payAmount": pay_amount,
            "payType": "fixed", "location": location, "isRemote": not bool(location)}
    resp = requests.post(f"{RENTAHUMAN_API}/bounties", json=data, headers=headers)
    return resp.text

agent = Agent(
    name="TaskDelegator",
    instructions="When the user needs something done in the physical world, search RentAHuman, evaluate humans, and hire them.",
    tools=[search_humans, create_bounty],
)
result = Runner.run_sync(agent, "Find a photographer in Austin, TX. Budget: $50/hr.")
```

## Key Observations for PCC Integration Assessment

1. **Direct relevance to PCC**: PCC involves physical-world capability — operators, hardware, robots, field verification. RentAHuman is explicitly a physical-world task delegation API. The overlap is direct.

2. **MCP native**: 52 MCP tools, `npx rentahuman-mcp` install. This can be added to PCC's MCP server config in minutes.

3. **Crypto payment support**: Human profiles list `currency: "USD" | "EUR" | "ETH" | "BTC" | "USDC"` and `cryptoWallets`. The ai-plugin.json description mentions "flexible payment options including stablecoins." This aligns with PCC's USDC/stablecoin payment infrastructure.

4. **Agent-first design**: The entire platform is designed for AI agents as the customer. The operator (human) is a secondary actor who funds escrow and approves pairing. This maps well to PCC's agent-first architecture.

5. **Ed25519 cryptographic identity**: Same key type PCC uses for verification. Could potentially integrate identity systems.

6. **Bounty model**: Matches PCC's MilestoneEscrow + task verification model. RentAHuman's bounty→escrow→confirm_delivery→release_payment flow is structurally identical to PCC's milestone lifecycle.

7. **Open endpoints**: `/api/humans` search requires no auth. An AI agent could search the workforce before any payment commitment.

8. **Integration path for PCC**: Add `rentahuman-mcp` to PCC's MCP server list, giving PCC agents the ability to dispatch human operators for physical verification tasks, field research, hardware setup, or any task that currently requires a human operator to be "standing by" within PCC's system.

9. **Competitor/partner consideration**: RentAHuman competes with PCC's operator layer but could also be a partner — PCC workers could list themselves on RentAHuman, and PCC's AI agents could source operators via RentAHuman's marketplace.
