## 1. Story Protocol Fundamentals

### What Is Story Protocol

Story Protocol is a purpose-built L1 blockchain for programmable intellectual property (IP). It brings IP on-chain by:
- Representing each piece of IP as an ERC-721 NFT
- Wrapping that NFT in an IP Account (ERC-6551 Token Bound Account)
- Attaching programmable licenses, royalty rules, and dispute mechanisms to the IP Account

The mainnet ("Homer") launched February 13, 2025. It is EVM-compatible and uses CometBFT consensus.

### Network Details

| Property | Value |
|---|---|
| Chain Name | Story |
| Chain ID | 1514 (0x5ea) |
| Native Token | IP (18 decimals) |
| Consensus | CometBFT (Cosmos SDK + EVM) |
| RPC (mainnet) | https://mainnet.storyrpc.io |
| RPC (testnet) | https://aeneid.storyrpc.io |
| Block Explorer | https://mainnet.storyscan.xyz |
| Testnet Name | Aeneid |
| EVM Compatible | Yes (full) |

### Core Primitives

**IP Asset**: An ERC-721 NFT registered into Story's global IPAssetRegistry. Registration deploys an IP Account.

**IP Account**: A modified ERC-6551 (Token Bound Account) bound to the NFT. Acts as the IP's smart contract identity. Stores licenses, tracks royalties, controls permissions. The `ipId` IS the IP Account address.

**Programmable IP License (PIL)**: On-chain legal agreements. Defines: commercial use, revenue share %, attribution, remixability, minting fees.

**Royalty Token**: Each IP Account automatically deploys an IP Royalty Vault with 100 Royalty Tokens. Each token = 1% of all revenue generated by that IP Asset. Can be distributed to collaborators — enabling DeFi on top of IP revenue.

**Derivative IP**: Child IP Asset that links to a parent via license terms. Creates automatic royalty flow up the ancestor chain.

## 4. Registering an IP Asset

Full flow: mint NFT + upload metadata to IPFS + register in one transaction.

```typescript
import {
  IpMetadata,
  PILFlavor,
  WIP_TOKEN_ADDRESS
} from "@story-protocol/core-sdk";
import { createHash } from "crypto";
import { parseEther } from "viem";

async function registerCapabilityAsIP(capability: PCCCapability) {
  // 1. Build IP metadata (IPA Metadata Standard)
  const ipMetadata: IpMetadata = {
    title: capability.name,
    description: capability.description,
    image: capability.thumbnailUrl,
    creators: [
      {
        name: capability.operatorName,
        address: capability.operatorAddress,
      }
    ],
    attributes: [
      { key: "capabilityType", value: capability.type },
      { key: "kernelId", value: capability.kernelId },
      { key: "assuranceTier", value: String(capability.assuranceTier) },
    ],
  };

  // 2. Build NFT metadata (ERC-721 standard)
  const nftMetadata = {
    name: `${capability.name} Capability Certificate`,
    description: `Soulbound capability certificate for ${capability.name} on Shop Kernel ${capability.kernelId}`,
    image: capability.thumbnailUrl,
  };

  // 3. Upload to IPFS (use existing Storacha/Helia integration)
  const ipIpfsHash = await uploadJSONToIPFS(ipMetadata);
  const nftIpfsHash = await uploadJSONToIPFS(nftMetadata);
  const ipHash = createHash("sha256").update(JSON.stringify(ipMetadata)).digest("hex");
  const nftHash = createHash("sha256").update(JSON.stringify(nftMetadata)).digest("hex");

  // 4. Register with commercial remix license
  // commercialRevShare: 5 means 5% of all derivative revenue goes to this IP
  const response = await client.ipAsset.registerIpAsset({
    nft: {
      type: "mint",
      spgNftContract: "0xc32A8a0FF3beDDDa58393d022aF433e78739FAbc", // SPG NFT contract
    },
    licenseTermsData: [{
      terms: PILFlavor.commercialRemix({
        commercialRevShare: 5, // 5% of derivative revenue
        defaultMintingFee: parseEther("0"), // free to license, revenue via escrow
        currency: WIP_TOKEN_ADDRESS,
      }),
    }],
    ipMetadata: {
      ipMetadataURI: `https://ipfs.io/ipfs/${ipIpfsHash}`,
      ipMetadataHash: `0x${ipHash}`,
      nftMetadataURI: `https://ipfs.io/ipfs/${nftIpfsHash}`,
      nftMetadataHash: `0x${nftHash}`,
    },
  });

  // response.ipId = the IP Account address (used as permanent ID)
  // response.txHash = the transaction hash
  return response;
}
```

## 5. Registering a Derivative IP Asset

When a job produces output (evidence of work), that output is a derivative of the original CSD/capability IP.

```typescript
async function registerJobEvidenceAsDerivative(
  parentIpId: string,      // the capability CSD's ipId
  licenseTermsId: string,  // the PIL license terms ID on parent
  jobEvidence: JobEvidence
) {
  // Build metadata for the job output / evidence bundle
  const ipMetadata = {
    title: `Job ${jobEvidence.jobId} Output`,
    description: `Evidence bundle for job ${jobEvidence.jobId} using ${jobEvidence.capabilityName}`,
    creators: [
      { name: jobEvidence.operatorName, address: jobEvidence.operatorAddress },
    ],
    attributes: [
      { key: "jobId", value: jobEvidence.jobId },
      { key: "parentCapabilityId", value: jobEvidence.capabilityId },
      { key: "completedAt", value: jobEvidence.completedAt },
    ],
  };

  const ipIpfsHash = await uploadJSONToIPFS(ipMetadata);
  const ipHash = createHash("sha256").update(JSON.stringify(ipMetadata)).digest("hex");

  const response = await client.ipAsset.registerIpAsset({
    nft: { type: "mint", spgNftContract: SPG_NFT_CONTRACT },
    derivData: {
      parentIpIds: [parentIpId],
      licenseTermsIds: [licenseTermsId],
    },
    ipMetadata: {
      ipMetadataURI: `https://ipfs.io/ipfs/${ipIpfsHash}`,
      ipMetadataHash: `0x${ipHash}`,
      nftMetadataURI: `https://ipfs.io/ipfs/${ipIpfsHash}`,
      nftMetadataHash: `0x${ipHash}`,
    },
  });

  return response; // response.ipId = derivative IP ID
}
```

## 6. PIL License Flavors

| Flavor | Commercial? | Revenue Share | Remixable? | Use Case |
|---|---|---|---|---|
| `PILFlavor.nonCommercialSocialRemixing()` | No | 0% | Yes | Open-source CSD profiles |
| `PILFlavor.commercialUse(...)` | Yes | 0% (pay to use) | No | Proprietary process recipes |
| `PILFlavor.commercialRemix(...)` | Yes | Configurable % | Yes | Revenue-sharing with designer |
| `PILFlavor.creativeCommonsAttribution()` | Yes | 0% | Yes | Community process library |

For PCC, `commercialRemix` is the most relevant: a CSD designer earns % of every job that uses their process definition.

## 7. Royalty Module: How Revenue Flows

### Architecture

Each IP Asset has an IP Royalty Vault with 100 Royalty Tokens. Revenue flows like this:

```
Job Payment (USDC/WIP)
    ↓
payRoyaltyOnBehalf(receiverIpId=jobEvidenceIP, payerIpId=clientAddress)
    ↓
Royalty Module routes % to each ancestor based on royalty stack
    ↓
Parent IP Royalty Vault receives its % automatically
    ↓
claimAllRevenue() pulls from vault to actual wallets
```

### Multi-Ancestor Royalty Stack (LAP Policy)

If CSD A → forked to CSD B (5% rev share) → used in Job C (10% total stack):
- Job C pays 100 WIP
- CSD B designer gets 5 WIP (5%)
- CSD A designer gets additional % (ancestor shares accumulate)
- Job operator keeps the rest

Current limits: up to 1024 ancestors, 8 parents per IP Asset.

### Paying Royalties

```typescript
// Scenario 1: Client tips an IP Asset (e.g., after a great job)
const payment = await client.royalty.payRoyaltyOnBehalf({
  receiverIpId: jobEvidenceIpId,
  payerIpId: zeroAddress, // external payer
  token: WIP_TOKEN_ADDRESS,
  amount: parseEther("10"),
});

// Scenario 2: Derivative pays owed revenue share to parent
const revShare = await client.royalty.payRoyaltyOnBehalf({
  receiverIpId: parentCsdIpId,    // parent CSD designer
  payerIpId: jobEvidenceIpId,     // the derivative job IP
  token: WIP_TOKEN_ADDRESS,
  amount: parseEther("5"),        // 5% of job revenue
});
```

### Claiming Revenue

```typescript
// Claim all revenue accumulated in the vault for an IP
const claimed = await client.royalty.claimAllRevenue({
  ancestorIpId: myCsdIpId,
  claimer: myWalletAddress, // must hold Royalty Tokens for this IP
  childIpIds: [jobEvidenceIpId1, jobEvidenceIpId2],
  royaltyPolicies: [LAP_POLICY_ADDRESS],
  currencyTokens: [WIP_TOKEN_ADDRESS],
});
```

### Royalty Token Distribution (Multi-Party Splits)

For a 3-party split (designer + operator + verifier):
```typescript
// After IP is registered, distribute Royalty Tokens
// Designer keeps 60, Operator gets 30, Verifier gets 10
// This gives them rights to 60/30/10% of IP revenue respectively
await client.ipAccount.execute({
  ipId: csdIpId,
  to: royaltyVaultAddress,
  data: encodeDistributeRoyaltyTokens([
    { recipient: designerAddress, amount: 60 },
    { recipient: operatorAddress, amount: 30 },
    { recipient: verifierAddress, amount: 10 },
  ]),
});
```

## 8. Dispute Module

Uses UMA Optimistic Oracle for arbitration.

### Flow

1. **Raise dispute**: Caller posts bond, submits evidence (IPFS hash of dispute document)
2. **Liveness period pt 1**: IP owner only can counter-dispute/appeal
3. **Liveness period pt 2**: Any address can counter-dispute
4. **Counter-dispute**: Challenger posts equal bond; escalates to UMA
5. **UMA resolution**: External oracle reviews evidence, makes binding judgment
6. **Verdict**: Winner gets both bonds; loser's IP can be flagged as infringing

### Burden of Proof

Disputer bears burden: must provide "clear, compelling, and verifiable evidence" beyond reasonable doubt. Evidence must be an IPFS-hosted document (<1 hour to review).

### PCC Relevance

Story's dispute module parallels PCC's challenge window in MilestoneEscrow:
- Challenge window = liveness period
- Evidence = IPFS-linked ZK proof bundles from @pcc/verifier
- Resolution = currently manual/automatic in PCC; Story adds decentralized oracle layer

## 9. Group Module

Enables collections of IPs under a shared umbrella with pooled royalties.

Use case for PCC: A "Manufacturing Process Library" could be registered as a Group IP:
- Multiple CSD designers contribute process definitions
- Each contributor holds Royalty Tokens proportional to their contribution
- When any CSD in the group is licensed, revenue flows to the pool
- Pool auto-distributes to token holders

```typescript
const group = await client.group.createGroup({
  groupPool: GROUP_POOL_ADDRESS, // EvenSplitGroupPool or custom
});
// Then add IPs to the group
await client.group.addIpsToGroup({
  groupIpId: group.groupId,
  ipIds: [csd1IpId, csd2IpId, csd3IpId],
});
```

## 10. PCC Integration Mapping

### Conceptual Mapping

| Story Protocol | PCC Equivalent | Integration Point |
|---|---|---|
| IP Asset | Capability StructureDefinition (CSD) | Publishing a CSD = registering IP on Story |
| IP Account (ERC-6551) | Capability Certificate (soulbound cNFT) | Attach Story IP Account to existing cNFT |
| PIL Commercial Remix | Capability Contract terms | Booking = licensing; rev share % = designer cut |
| Royalty Token | Multi-party revenue split | Designer/operator/verifier % distribution |
| Derivative IP | Job Evidence Bundle | Job output = derivative of CSD IP |
| IP Royalty Vault | Payment accumulator | Replaces manual escrow split calculation |
| Royalty flow (child→parent) | Revenue share in MilestoneEscrow | Automated by Story vs. manual calculation |
| Dispute Module | Challenge Window | Same concept; Story adds UMA oracle layer |
| Group Module | Process Library collection | Set of related CSDs with pooled royalties |
| WIP Token | Payment currency | Cross-chain: USDC in PCC escrow, WIP on Story |
| License Token | Booking confirmation | Minting a license token = confirmed booking |

### The Core Value Add

PCC already has MilestoneEscrow for payments and challenge windows. Story Protocol adds:
1. **Designer IP rights** — the person who created the CSD profile earns % of ALL jobs using it, forever
2. **Derivative provenance** — every job output is traceable back through the IP chain
3. **Decentralized dispute resolution** — UMA oracle arbitration vs. manual resolution
4. **Tradeable revenue streams** — Royalty Tokens let designers sell future earnings on secondary markets
5. **Cross-ecosystem discoverability** — CSDs appear in Story Protocol ecosystem explorers

## 11. Collaborative Labor & IP Chains

### Multi-Step Workflow IP Chain

PCC supports multi-step protocols (CNC → anodize → assemble → ship). Each step:
1. Uses a CSD profile (IP Asset = parent)
2. Produces evidence (registered as derivative IP)
3. Triggers next step (derivative of previous step's output)

Result: A chain of IP Assets tracking provenance:
```
CSD_CNC (root IP, designer=Alice)
  → Job_CNC_Run_1 (derivative, operator=Bob)
  → CSD_Anodize (root IP, designer=Carol)
    → Job_Anodize_Run_1 (derivative, operator=Dave)
      → Final_Assembly (derivative of all above)
```

Revenue from Final_Assembly flows back automatically to Alice, Bob, Carol, Dave in configured percentages.

### Per-Step Revenue Split Structure

For a typical PCC job with 3 parties:
```
Royalty Tokens (100 total):
- CSD Designer (Alice): 15 tokens → 15% of job IP revenue
- Machine Operator (Bob): 70 tokens → 70% of job IP revenue
- Verifier (decentralized): 15 tokens → 15% of job IP revenue

Derivative rev share back to parent CSD:
- commercialRevShare: 5% → goes to parent CSD's IP Royalty Vault
- Parent CSD designer earns from every derivative job forever
```

### Micropayment Reuse Royalties

If someone forks a CSD (derives a new CSD from an existing one):
1. Forked CSD is registered as derivative IP
2. License terms specify % of forked CSD's revenue goes to original designer
3. Every job that uses the fork → triggers royalty flow → original designer earns

This creates a network effect for quality CSD authors: popular process definitions generate perpetual passive income.

## 12. Revenue-Generating NFTs (Machine Certificates)

### PCC Capability Certificate (Soulbound cNFT) + Story

Current PCC flow:
- Machine is onboarded → CapabilityCertificateService mints soulbound cNFT
- cNFT represents the machine's verified capability at an assurance tier

Story Protocol enhancement:
1. When minting a cNFT, ALSO register it as an IP Asset on Story
2. The machine operator holds Royalty Tokens for that IP
3. Every time someone licenses the machine capability (books a job):
   - License minting fee (if set) goes to IP Royalty Vault
   - Job completion payment triggers rev-share to IP Vault
4. The cNFT is soulbound (non-transferable) but Royalty Tokens ARE transferable
   - Operator can sell 10 Royalty Tokens to an investor = selling 10% of future earnings
   - This is the DePIN revenue model on-chain

### Comparison with DePIN Models

| Model | Revenue Source | Token | Transferable? |
|---|---|---|---|
| Helium | Network rewards epochs | HNT/MOBILE | Yes (hotspot NFT tradeable) |
| Hivemapper | Map contribution rewards | HONEY | Yes |
| PCC (current) | Escrow milestones | USDC | No |
| PCC + Story | Escrow + IP royalties + reuse fees | WIP + USDC | Royalty Tokens yes; cNFT no |

Key difference from Helium/Hivemapper: Story Protocol adds IP provenance on top of the reward mechanism. A PCC machine is not just earning rewards — it's generating IP every time it runs a job.

## 14. New Smart Contracts Needed

### StoryCapabilityAdapter.sol

A thin adapter contract that:
1. Holds the `spgNftContract` for PCC's capability certificates
2. Provides `registerCapabilityIP(capabilityId, metadata)` — wrapper for Story registration
3. Emits events that the gateway can listen to

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.26;

import { IIPAssetRegistry } from "@story-protocol/protocol-core/interfaces/registries/IIPAssetRegistry.sol";
import { ILicensingModule } from "@story-protocol/protocol-core/interfaces/modules/licensing/ILicensingModule.sol";

contract StoryCapabilityAdapter {
    IIPAssetRegistry public immutable IP_ASSET_REGISTRY;
    ILicensingModule public immutable LICENSING_MODULE;

    // capabilityId => Story ipId
    mapping(bytes32 => address) public capabilityIpIds;

    // jobId => Story derivative ipId
    mapping(bytes32 => address) public jobEvidenceIpIds;

    event CapabilityIPRegistered(bytes32 indexed capabilityId, address ipId);
    event JobEvidenceIPRegistered(bytes32 indexed jobId, address ipId, address parentIpId);

    constructor(address ipAssetRegistry, address licensingModule) {
        IP_ASSET_REGISTRY = IIPAssetRegistry(ipAssetRegistry);
        LICENSING_MODULE = ILicensingModule(licensingModule);
    }
}
```

## 17. Open Questions / Risks

1. **Currency mismatch**: PCC uses USDC in MilestoneEscrow; Story uses WIP on chain 1514. Need a bridge or off-chain trigger pattern. Off-chain trigger (Option 1 in Phase C) avoids this for now.

2. **Soulbound vs. transferable**: PCC cNFTs are soulbound; Story IP Assets are transferable ERC-721s. Solution: Use a separate Story-registered NFT for IP ownership; keep cNFT as the device credential. They're different tokens serving different purposes.

3. **Gas costs on Story chain**: Registering every job as a derivative IP would be expensive at scale. Consider: only register CSDs as IP Assets; use off-chain attestations for individual job outputs, only registering high-value or disputed jobs on-chain.

4. **Multi-chain complexity**: PCC currently targets Ethereum/Base for escrow contracts. Story is chain 1514. The gateway would need to manage two chains simultaneously. The `chain-config.ts` file in `@pcc/contracts` would need a new `story` entry alongside `base-sepolia`/`sepolia`.

5. **IPFS requirement**: Story metadata must be on IPFS. PCC already has Storacha/Helia integration in `@pcc/kernel/src/evidence-storage.ts` — this is covered with zero extra work.

6. **testnet vs mainnet**: Aeneid testnet shares contract addresses with mainnet (same addresses both chains). Safe to develop on Aeneid and deploy to mainnet without address changes.

7. **CapabilityCertificate vs Story IP**: The existing `CapabilityCertificate` type in `@pcc/spec/src/types/depin.ts` uses Solana (mpl-core/Bubblegum). Story is EVM. These are two separate NFT systems for two different purposes — do NOT conflate them. The cNFT remains the device credential on Solana; a Story IP Asset is the IP ownership record on Story L1.

### StoryIPService skeleton (packages/contracts/ts/story-ip-service.ts)

```typescript
/**
 * StoryIPService — registers PCC capabilities and job evidence as Story Protocol IP Assets.
 *
 * Each Capability published on PCC is registered as an IP Asset on Story Network (chain 1514).
 * Job evidence bundles are registered as derivative IPs, creating a full provenance chain.
 * Royalty Tokens are distributed to designer/operator/verifier for multi-party revenue splits.
 *
 * Uses @story-protocol/core-sdk with viem (already a PCC dependency).
 *
 * Network selection:
 *   STORY_NETWORK=story-aeneid  → Aeneid testnet (default)
 *   STORY_NETWORK=story         → Story mainnet
 *   STORY_RPC_URL               → Override RPC
 *   STORY_PRIVATE_KEY           → Wallet private key (separate from PCC wallet)
 */

import { http } from "viem";
import { privateKeyToAccount } from "viem/accounts";
import {
  StoryClient,
  type StoryConfig,
  PILFlavor,
  WIP_TOKEN_ADDRESS,
} from "@story-protocol/core-sdk";
import { createHash } from "crypto";
import { parseEther, zeroAddress } from "viem";
import type { Capability } from "@pcc/spec";
import type {
  StoryIPRegistration,
  StoryRoyaltySplit,
  StoryDerivativeLink,
} from "@pcc/spec";

// ── Types ───────────────────────────────────────────────────────

export interface JobEvidenceForStory {
  jobId: string;
  capabilityId: string;
  capabilityName: string;
  operatorName: string;
  operatorAddress: string;
  evidenceBundleHash: string;  // from MilestoneEscrow
  completedAt: string;
  ipfsCid?: string;            // from Storacha/Helia
}

// ── Service ─────────────────────────────────────────────────────

export class StoryIPService {
  private client: ReturnType<typeof StoryClient.newClient>;
  private mock: boolean;

  // In-memory store for mock mode (capabilityId → ipId)
  private mockRegistry = new Map<string, StoryIPRegistration>();

  constructor(options: { mock?: boolean } = {}) {
    this.mock = options.mock ?? process.env.STORY_MOCK !== "false";

    if (!this.mock) {
      const privateKey = process.env.STORY_PRIVATE_KEY;
      if (!privateKey) throw new Error("STORY_PRIVATE_KEY required for Story integration");

      const network = process.env.STORY_NETWORK ?? "story-aeneid";
      const rpcUrl = process.env.STORY_RPC_URL ??
        (network === "story" ? "https://mainnet.storyrpc.io" : "https://aeneid.storyrpc.io");

      const config: StoryConfig = {
        account: privateKeyToAccount(`0x${privateKey}`),
        transport: http(rpcUrl),
        chainId: network === "story" ? "mainnet" : "aeneid",
      };

      this.client = StoryClient.newClient(config);
    }
  }

  /**
   * Register a PCC Capability as a Story Protocol IP Asset.
   * Called when a capability is first published to the marketplace.
   * Returns the Story ipId (IP Account address) and license terms ID.
   */
  async registerCapabilityAsIP(
    capability: Capability,
    options: {
      designerAddress: string;
      designerName: string;
      commercialRevShare?: number; // default 5%
      ipfsCidOverride?: string;    // if already on IPFS
    }
  ): Promise<StoryIPRegistration> {
    if (this.mock) {
      return this._mockRegister(capability.id);
    }

    const revShare = options.commercialRevShare ?? 5;

    const ipMetadata = {
      title: capability.name,
      description: capability.description ?? `PCC Capability: ${capability.type}`,
      creators: [{
        name: options.designerName,
        address: options.designerAddress,
      }],
      attributes: [
        { key: "pcc:capabilityType", value: capability.type },
        { key: "pcc:kernelId", value: capability.kernelId },
        { key: "pcc:assuranceTiers", value: capability.assuranceTiers.join(",") },
        { key: "pcc:pricing:baseCost", value: `${capability.pricing.baseCost} ${capability.pricing.currency}` },
      ],
    };

    const nftMetadata = {
      name: `${capability.name} — PCC IP Certificate`,
      description: `Programmable IP certificate for PCC capability: ${capability.name}. Assurance tiers: ${capability.assuranceTiers.join(", ")}.`,
      image: `https://pcc.ai/capability/${capability.id}/og.png`,
    };

    const ipHash = createHash("sha256").update(JSON.stringify(ipMetadata)).digest("hex");
    const nftHash = createHash("sha256").update(JSON.stringify(nftMetadata)).digest("hex");

    // Use IPFS CID override if already uploaded via Storacha
    const ipIpfsUri = options.ipfsCidOverride
      ? `ipfs://${options.ipfsCidOverride}`
      : `ipfs://${await this._uploadToIPFS(ipMetadata)}`;

    const response = await this.client.ipAsset.registerIpAsset({
      nft: {
        type: "mint",
        spgNftContract: this._spgContract(),
      },
      licenseTermsData: [{
        terms: PILFlavor.commercialRemix({
          commercialRevShare: revShare,
          defaultMintingFee: parseEther("0"),
          currency: WIP_TOKEN_ADDRESS,
        }),
      }],
      ipMetadata: {
        ipMetadataURI: ipIpfsUri,
        ipMetadataHash: `0x${ipHash}`,
        nftMetadataURI: ipIpfsUri,
        nftMetadataHash: `0x${nftHash}`,
      },
    });

    return {
      ipId: response.ipId!,
      txHash: response.txHash!,
      licenseTermsId: response.licenseTermsIds?.[0]?.toString() ?? "0",
      royaltyVaultAddress: "", // populated via separate query
    };
  }

  /**
   * Register a completed job's evidence bundle as a Story derivative IP.
   * Called by the gateway after a MilestoneReleased event from MilestoneEscrow.
   */
  async registerJobEvidenceAsDerivative(
    evidence: JobEvidenceForStory,
    parentRegistration: StoryIPRegistration
  ): Promise<StoryDerivativeLink> {
    if (this.mock) {
      return this._mockDerivative(evidence.jobId, parentRegistration.ipId);
    }

    const ipMetadata = {
      title: `Job Evidence: ${evidence.jobId}`,
      description: `Completed job evidence for capability ${evidence.capabilityName}`,
      creators: [{ name: evidence.operatorName, address: evidence.operatorAddress }],
      attributes: [
        { key: "pcc:jobId", value: evidence.jobId },
        { key: "pcc:capabilityId", value: evidence.capabilityId },
        { key: "pcc:evidenceHash", value: evidence.evidenceBundleHash },
        { key: "pcc:completedAt", value: evidence.completedAt },
      ],
    };

    const ipHash = createHash("sha256").update(JSON.stringify(ipMetadata)).digest("hex");
    const ipfsUri = evidence.ipfsCid
      ? `ipfs://${evidence.ipfsCid}`
      : `ipfs://${await this._uploadToIPFS(ipMetadata)}`;

    const response = await this.client.ipAsset.registerIpAsset({
      nft: { type: "mint", spgNftContract: this._spgContract() },
      derivData: {
        parentIpIds: [parentRegistration.ipId as `0x${string}`],
        licenseTermsIds: [BigInt(parentRegistration.licenseTermsId)],
      },
      ipMetadata: {
        ipMetadataURI: ipfsUri,
        ipMetadataHash: `0x${ipHash}`,
        nftMetadataURI: ipfsUri,
        nftMetadataHash: `0x${ipHash}`,
      },
    });

    return {
      parentIpId: parentRegistration.ipId,
      childIpId: response.ipId!,
      licenseTermsId: parentRegistration.licenseTermsId,
      commercialRevShare: 5, // configured on the parent
    };
  }

  /**
   * Pay royalty to a parent IP after job completion.
   * Called after MilestoneEscrow releaseMilestone().
   * Amount is denominated in WIP (caller must pre-fund gateway wallet with WIP).
   */
  async payJobRoyalty(
    parentIpId: string,
    derivativeIpId: string,
    amountWIP: string // e.g. "1.5" WIP
  ): Promise<string> {
    if (this.mock) {
      return `mock_tx_${Date.now()}`;
    }

    const result = await this.client.royalty.payRoyaltyOnBehalf({
      receiverIpId: parentIpId as `0x${string}`,
      payerIpId: derivativeIpId as `0x${string}`,
      token: WIP_TOKEN_ADDRESS,
      amount: parseEther(amountWIP),
    });

    return result.txHash!;
  }

  /**
   * Claim all accumulated revenue from an IP's royalty vault.
   */
  async claimRevenue(
    ipId: string,
    claimer: string,
    childIpIds: string[]
  ): Promise<string> {
    if (this.mock) {
      return `mock_claim_tx_${Date.now()}`;
    }

    const result = await this.client.royalty.claimAllRevenue({
      ancestorIpId: ipId as `0x${string}`,
      claimer: claimer as `0x${string}`,
      childIpIds: childIpIds as `0x${string}`[],
      royaltyPolicies: [],      // SDK fills from on-chain data
      currencyTokens: [WIP_TOKEN_ADDRESS],
    });

    return result.txHash!;
  }

  // ── Private helpers ─────────────────────────────────────────────

  private _spgContract(): `0x${string}` {
    // SPG NFT contract for minting capability NFTs
    // This is the Aeneid testnet SPG contract; override for mainnet via env
    return (process.env.STORY_SPG_CONTRACT ?? "0xc32A8a0FF3beDDDa58393d022aF433e78739FAbc") as `0x${string}`;
  }

  private async _uploadToIPFS(data: object): Promise<string> {
    // In real usage: delegate to @pcc/kernel EvidenceStorageService (Storacha/Helia)
    // For now: return a deterministic mock CID
    const hash = createHash("sha256").update(JSON.stringify(data)).digest("hex");
    return `bafybeig${hash.slice(0, 50)}`;
  }

  private _mockRegister(capabilityId: string): StoryIPRegistration {
    const ipId = `0x${createHash("sha256").update(`ip_${capabilityId}`).digest("hex").slice(0, 40)}`;
    const reg: StoryIPRegistration = {
      ipId,
      txHash: `0x${createHash("sha256").update(`tx_${capabilityId}`).digest("hex")}`,
      licenseTermsId: "1",
      royaltyVaultAddress: `0x${createHash("sha256").update(`vault_${capabilityId}`).digest("hex").slice(0, 40)}`,
    };
    this.mockRegistry.set(capabilityId, reg);
    return reg;
  }

  private _mockDerivative(jobId: string, parentIpId: string): StoryDerivativeLink {
    const childIpId = `0x${createHash("sha256").update(`child_${jobId}`).digest("hex").slice(0, 40)}`;
    return {
      parentIpId,
      childIpId,
      licenseTermsId: "1",
      commercialRevShare: 5,
    };
  }
}
```
